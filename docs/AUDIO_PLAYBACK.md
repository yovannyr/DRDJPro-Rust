# Audio loading and mixer slice

The default application and `--gui` open the OS default Rodio/CPAL audio output and start with two empty decks. Each deck has a native MP3/WAV file selector. `--gui <deck-a.mp3> <deck-b.wav>` still preloads both tracks paused. `--demo` explicitly selects the simulated UI without opening audio hardware. Missing audio output is reported to stderr and startup fails; automatic device recovery is deferred.

## Behavior and boundaries

- File selection and decoding from the GUI run on one named worker, with at most one selection/load outstanding. Both Load buttons are disabled until it completes. Playback of the current tracks continues while choosing/decoding. Cancel and errors leave both existing decks intact; errors appear in the status line.
- A successful load replaces only the selected deck, paused at zero, with the filename displayed. Empty, unreadable, unsupported and undecodable files are rejected. MP3/WAV only; the decoder can accept a partially damaged file if it produces complete samples. Strict corruption detection is deferred.
- PCM is prepared before installation, limited to 256 MiB per track (roughly 12.7 minutes of stereo 44.1 kHz f32). Two retained decks plus old/new data during replacement and temporary decoding copies can use considerably more memory. This is a bounded prototype, not a streaming library implementation.
- Play/Pause, Cue and end/restart use the same application-owned deck engine. Cue installs a fresh paused source at zero, including after EOF. Reload and Cue avoid Rodio's blocking stop/append and seek feedback waits; prepared buffers share sample storage through Arc.
- Channel A/B and crossfader sliders apply actual sink volumes. Gains are linear: `A = channel_a * (1 - crossfader)`, `B = channel_b * crossfader`. Initial channel levels are 1, crossfader 0.5. This is not an equal-power DJ curve; no limiter is provided.
- Elapsed/total time and percent use decoded frame duration and Rodio's source position. The GUI refreshes every 33 ms; sink controls/position have approximately 5 ms granularity and are not corrected for device output latency. EOF displays stopped at 100%; Play restarts. The position slider seeks its own deck while preserving Play/Pause and mixer gains. Values are clamped to 0–100%; non-finite requests are rejected without changing playback. Seeking to 100% stops; Play restarts from zero. Seeking backward after EOF remains paused. The GUI timer continues to report the source position including the seek offset.
- Seeking clones the shared PCM source, moves its cursor on the control plane and installs a replacement sink. It does not call the blocking Sink::try_seek. Each replacement sink contains one fixed-format source; a small output adapter reports its actual channel count/sample rate from the start, avoiding Rodio queue startup metadata that initially describes mono/44.1 kHz. No decoding or file access occurs during seeking. Like existing Cue/reload, replacement can have a short control-propagation overlap (approximately 5 ms); click suppression and sample-accurate output synchronization remain open.
- Each audio deck now displays a real static peak overview of its complete track. Up to 256 equal-time bins take the maximum absolute sample across channels, calculated from the same PCM as playback before installation. Peaks are not normalized; only their visual heights are clamped to 0–1. The moving marker uses engine percent and clicking the overview seeks that deck. Prepared tracks share immutable peak storage and the controller replaces GUI models only when track data changes. A second, zoomable peak-envelope view follows the playhead with 2–32 seconds visible per deck. Its peaks are prepared once per 256 PCM frames, with peak magnitudes and three f64 band-energy sums per 256-frame block. Those retained values together use at most 7 MiB per mono track at the existing PCM limit (less for stereo), excluding small overview, allocation and GUI metadata. Re-binning a visible range touches only prepared envelope data on the GUI control plane. Clicking it seeks within that range and preserves transport/gains. The GUI refresh remains 33 ms, with no rendering or latency guarantee. Frequency colors are computed on the loader with complementary first-order filters around 200 Hz and 2 kHz. Relative low/mid/high energy blends red/green/blue; this is approximate, not spectral measurement or an audio EQ. Heights and playback are untouched. Stereo energy is accumulated separately per channel. Synthetic bars remain only in explicit --demo mode; detail zoom is disabled there. Slint remains provisional; no visual review or physical listening test was performed.

## Manual beatgrid

The grid is off until explicitly set by the user. GRID HERE validates the requested BPM (40–240), anchors a 4/4 downbeat at the current source position and changes only deck metadata. The GUI accepts whole BPM values; the domain timing supports fractional BPM. Visible detail lines are calculated from absolute beat indices rather than repeatedly adding rounded durations. The UI range of at most 32 seconds/240 BPM yields at most 129 lines. Negative beat indices extend the grid backward before an anchor, within the track viewport.

Play/Pause, seek, Cue and EOF/restart preserve the grid; successful reload resets that deck, while failed loading leaves it intact. GRID OFF clears it. No persistence, automatic beat/downbeat alignment, variable-tempo tracking, meter detection, audio time stretching or synchronization is provided. A separate experimental BPM suggestion is available as described below. The existing source-clock/device-latency limitations apply to the anchor.

## Experimental BPM suggestion

Track preparation now analyzes at most the first 60 seconds at sample rates of at least 8 kHz; at least 8 seconds of audio is required. Approximately 200 Hz power frames average squared channel samples without stereo cancellation. A 10-frame smoothing window and positive deviation from recent smoothed history form a novelty envelope. Weak novelty is rejected; normalized lag correlation searches 40–240 BPM, prefers the first near-best local maximum and interpolates its lag. The fixed thresholds are heuristics, not calibrated confidence or musical accuracy guarantees.

The estimate is immutable track data and is computed on the loader, not an audio callback or the GUI timer. USE ~ is disabled without a candidate. Clicking it only copies rounded whole BPM into the pending field; it neither applies a grid nor changes playback. Existing manual grids remain intact until explicitly replaced/cleared. Error/cancel preserve the old track's suggestion, while successful reload replaces/removes it independently per deck. The domain retains a fractional estimate; the current manual GUI field is integer-only.

Synthetic pulse, silence/tone/noise, stereo and duration-cap tests validate the algorithm's defined regression cases. A real-music benchmark corpus has not been evaluated. Sparse intros, tempo changes, subdivisions and half/double-tempo ambiguity can yield no suggestion or an incorrect one. Manual review and anchor placement remain necessary; automatic grid/downbeat analysis is still open.

## Automated evidence

`cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test`, and `cargo build --release` are the local acceptance commands. `build.rs` enables Slint debug info directly so accessibility tests work without CI-only environment configuration. Cargo.lock pins the application's dependency resolution.

Headless tests use the same Rodio mixer/sinks and GUI controller without an output device. They cover selector callback wiring with an injected picker, actual worker decode for MP3/WAV, paused load, independent transport, reload, Cue, EOF/restart, failure/cancel preservation, bounded load requests, actual accessible mixer/position slider actions, finite/clamped seek input, MP3 seeking, transport/gain preservation during seeking, and correct rendered stereo samples before/after backward and forward jumps. Offline rendering asserts mixed sample values at crossfader endpoints, center, channel attenuation and mute; it also checks position advance/freeze. The PCM file is removed before rendering to confirm playback does not depend on open input files. Bundled generated MP3 and synthetic WAV fixtures make normal local tests independent of downloads. The optional DRDJ_AUDIO_TEST_FILE override remains available for the analysis test.

Offline render timings are diagnostic measurements of CPU rendering, not device latency, callback deadline measurements or proof of lock/allocation freedom. Rodio 0.21.1 itself uses mutexes and queues in its mixer/sink path. There is no custom real-time callback in this slice, and professional real-time acceptance remains open.

## CLI tools retained

`--analyze <file>` decodes and reports metrics without audio hardware. `--play <file>` and `--mix <a> <b>` use the same prepared tracks and default physical output, blocking until playback ends. These CLI paths preload synchronously before showing any GUI.

Next scope requires review: real-music BPM validation, automatic beat/downbeat/key analysis, click-free/sample-accurate seeking, streaming decoding/memory policy, device loss, headphone routing, EQ/limiting and real hardware performance are not part of this change.


## Software Keylock

Enable KEYLOCK in either deck cue panel or press MC4000 Key Lock. Tempo processing runs on background workers; pending tempo changes keep the previous prepared rate until the newest requested buffer is available. The original PCM, duration, waveform/grid and source-frame timeline remain authoritative. Prepared PCM is sampled by the renderer at mapped source coordinates. No DSP call or native allocation is made by the Keylock rendering branch. Prepared buffers travel with track ownership and retirement.

There is at most one running job and one latest tempo request per deck and at most two native DSP workers globally. Cancellation discards results before/after the non-interruptible whole-clip native operation. Each input/output PCM buffer is capped at 67,108,864 samples; original PCM, copies and DSP allocations are additional. Failure preserves the previously active prepared audio. Source replacement invalidates pending requests/results. Keylock is runtime per-deck state and is not persisted.

Continuous Sync and nudge with active Keylock are rejected in this version. Whole-track preparation may take time; this is not a streaming low-latency time-stretch implementation. Activating/deactivating or adopting a new tempo replaces the prepared render source; click-free listening, hardware latency and subjective music quality remain unqualified. The MC4000 Keylock LED follows adopted state after startup choreography.
