# Audio loading and mixer slice

The default application and `--gui` open the OS default Rodio/CPAL audio output and start with two empty decks. Each deck has a native MP3/WAV file selector. `--gui <deck-a.mp3> <deck-b.wav>` still preloads both tracks paused. `--demo` explicitly selects the simulated UI without opening audio hardware. Missing audio output is reported to stderr and startup fails; automatic device recovery is deferred.

## Behavior and boundaries

- File selection and decoding from the GUI run on one named worker, with at most one selection/load outstanding. Both Load buttons are disabled until it completes. Playback of the current tracks continues while choosing/decoding. Cancel and errors leave both existing decks intact; errors appear in the status line.
- A successful load replaces only the selected deck, paused at zero, with the filename displayed. Empty, unreadable, unsupported and undecodable files are rejected. MP3/WAV only; the decoder can accept a partially damaged file if it produces complete samples. Strict corruption detection is deferred.
- PCM is prepared before installation, limited to 256 MiB per track (roughly 12.7 minutes of stereo 44.1 kHz f32). Two retained decks plus old/new data during replacement and temporary decoding copies can use considerably more memory. This is a bounded prototype, not a streaming library implementation.
- Play/Pause, Cue and end/restart use the same application-owned deck engine. Cue installs a fresh paused source at zero, including after EOF. Reload and Cue avoid Rodio's blocking stop/append and seek feedback waits; prepared buffers share sample storage through Arc.
- Channel A/B and crossfader sliders apply actual sink volumes. Gains are linear: `A = channel_a * (1 - crossfader)`, `B = channel_b * crossfader`. Initial channel levels are 1, crossfader 0.5. This is not an equal-power DJ curve; no limiter is provided.
- Elapsed/total time and percent use decoded frame duration and Rodio's source position. The GUI refreshes every 33 ms; sink controls/position have approximately 5 ms granularity and are not corrected for device output latency. EOF displays stopped at 100%; Play restarts. The position slider seeks its own deck while preserving Play/Pause and mixer gains. Values are clamped to 0–100%; non-finite requests are rejected without changing playback. Seeking to 100% stops; Play restarts from zero. Seeking backward after EOF remains paused. The GUI timer continues to report the source position including the seek offset.
- Seeking clones the shared PCM source, moves its cursor on the control plane and installs a replacement sink. It does not call the blocking Sink::try_seek. Each replacement sink contains one fixed-format source; a small output adapter reports its actual channel count/sample rate from the start, avoiding Rodio queue startup metadata that initially describes mono/44.1 kHz. No decoding or file access occurs during seeking. Like existing Cue/reload, replacement can have a short control-propagation overlap (approximately 5 ms); click suppression and sample-accurate output synchronization remain open.
- Each audio deck now displays a real static peak overview of its complete track. Up to 256 equal-time bins take the maximum absolute sample across channels, calculated from the same PCM as playback before installation. Peaks are not normalized; only their visual heights are clamped to 0–1. The moving marker uses engine percent and clicking the overview seeks that deck. Prepared tracks share immutable peak storage and the controller replaces GUI models only when track data changes. A second, zoomable peak-envelope view follows the playhead with 2–32 seconds visible per deck. Its peaks are prepared once per 256 PCM frames, with peak magnitudes and three f64 band-energy sums per 256-frame block. Those retained values together use at most 7 MiB per mono track at the existing PCM limit (less for stereo), excluding small overview, allocation and GUI metadata. Re-binning a visible range touches only prepared envelope data on the GUI control plane. Clicking it seeks within that range and preserves transport/gains. The GUI refresh remains 33 ms, with no rendering or latency guarantee. Frequency colors are computed on the loader with complementary first-order filters around 200 Hz and 2 kHz. Relative low/mid/high energy blends red/green/blue; this is approximate, not spectral measurement or an audio EQ. Heights and playback are untouched. Stereo energy is accumulated separately per channel. Synthetic bars remain only in explicit --demo mode; detail zoom is disabled there. Slint remains provisional; no visual review or physical listening test was performed.

## Manual beatgrid

The grid is off until explicitly set by the user. GRID HERE validates the requested BPM (40–240), anchors a 4/4 downbeat at the current source position and changes only deck metadata. The GUI accepts whole BPM values; the domain timing supports fractional BPM. Visible detail lines are calculated from absolute beat indices rather than repeatedly adding rounded durations. The UI range of at most 32 seconds/240 BPM yields at most 129 lines. Negative beat indices extend the grid backward before an anchor, within the track viewport.

Play/Pause, seek, Cue and EOF/restart preserve the grid; successful reload resets that deck, while failed loading leaves it intact. GRID OFF clears it. No persistence, automatic beat/downbeat alignment, variable-tempo tracking, meter detection, audio time stretching or synchronization is provided. A separate experimental BPM suggestion is available as described below. The existing source-clock/device-latency limitations apply to the anchor.

## Experimental BPM suggestion

Track preparation now analyzes at most the first 60 seconds at sample rates of at least 8 kHz; at least 8 seconds of audio is required. Approximately 200 Hz power frames average squared channel samples without stereo cancellation. A 10-frame smoothing window and positive deviation from recent smoothed history form a novelty envelope. Weak novelty is rejected; normalized lag correlation searches 40–240 BPM, prefers the first near-best local maximum and interpolates its lag. The fixed thresholds are heuristics, not calibrated confidence or musical accuracy guarantees.

The estimate is immutable track data and is computed on the loader, not an audio callback or the GUI timer. USE ~ is disabled without a candidate. Clicking it only copies rounded whole BPM into the pending field; it neither applies a grid nor changes playback. Existing manual grids remain intact until explicitly replaced/cleared. Error/cancel preserve the old track's suggestion, while successful reload replaces/removes it independently per deck. The domain retains a fractional estimate; the current manual GUI field is integer-only.

Synthetic pulse, silence/tone/noise, stereo and duration-cap tests validate the algorithm's defined regression cases. A real-music benchmark corpus has not been evaluated. Sparse intros, tempo changes, subdivisions and half/double-tempo ambiguity can yield no suggestion or an incorrect one. Manual review and anchor placement remain necessary; automatic grid/downbeat analysis is still open.

## CLI tools retained

`--analyze <file>` decodes and reports metrics without audio hardware. `--play <file>` and `--mix <a> <b>` use the same prepared tracks and default physical output, blocking until playback ends. These CLI paths preload synchronously before showing any GUI.

Next scope requires review: real-music BPM validation, automatic beat/downbeat/key analysis, click-free/sample-accurate seeking, streaming decoding/memory policy, device loss, headphone routing, EQ/limiting and real hardware performance are not part of this change.


## Software Keylock

Enable KEYLOCK in either deck cue panel or press MC4000 Key Lock. Tempo processing runs on background workers; pending tempo changes keep the previous prepared rate until the newest requested buffer is available. The original PCM, duration, waveform/grid and source-frame timeline remain authoritative. Prepared PCM is sampled by the renderer at mapped source coordinates. No native DSP call or allocation is made by the Keylock rendering branch. Bounded Rust overlap/add processing handles short nudge corrections. Prepared buffers travel with track ownership and retirement.

There is at most one running job and one latest tempo request per deck and at most two native DSP workers globally. Cancellation discards results before/after the non-interruptible whole-clip native operation. Each input/output PCM buffer is capped at 67,108,864 samples; original PCM, copies and DSP allocations are additional. Failure preserves the previously active prepared audio. Source replacement invalidates pending requests/results. Keylock is runtime per-deck state and is not persisted.

A Keylock reference deck can drive tempo matching, phase alignment and continuous Sync of a coupled-speed follower. One-shot tempo matching also supports a Keylock target: it captures the target factor when requested, prepares it asynchronously, and retains the old factor until adoption without a phase-alignment command. This is not ongoing following of later reference changes. A Keylock follower now supports phase alignment and continuous Sync after preparation of the matched base tempo. The SYNC action performs that preparation automatically when necessary, waits for fresh playing render frames and then acquires phase. The existing momentary +/-2% nudge controls now work on a prepared Keylock track, retaining pitch through bounded overlap/add correction. Nudge waits while Keylock preparation is pending. Sync acquisition blocks unrelated pending Keylock jobs; a request-owned preparation is tracked separately from active following and is cancellable. Starting an unrelated preparation stops the existing Sync request/session. Whole-track preparation may take time; this is not a streaming low-latency time-stretch implementation. Activating/deactivating or adopting a new tempo replaces the prepared render source; click-free listening, hardware latency and subjective music quality remain unqualified. MC4000 LEDs now remain continuously lit after startup choreography; Keylock state is shown in the GUI.

### Keylock handoff smoothing

Playing same-track Keylock buffer replacements use a five-ms signal dezipper. The first output sample per L/R channel equals the prior renderer's last actual sample; the initial difference from the new signal decays linearly to zero over the window. This is a finite signal correction, not a crossfade between two continuing sources. Pause/EOF stay silent, explicit seek cancels correction, and additional output channels remain unchanged. The renderer retains only the old small atomic control, never extra old PCM. No allocation, lock, wait or native DSP is introduced in the sample path. This bounds the switching discontinuity but does not establish subjective music/transient quality, device latency or seamless transitions.

### Small dynamic Keylock correction

Nudge now uses a bounded WSOLA-style overlap/add stage around the prepared tempo. It chooses shared stereo anchors once per 20-ms hop using a fixed sixteen-point, coarse/fine waveform search within at most twenty ms (radius capped at 3840 output frames). Two overlapping reads advance at the neutral prepared pitch rate while the authoritative source clock immediately follows the requested nudge rate. Stereo channels share anchors and weights, mono duplication/output mapping stays in the renderer, and sample positions wrap within an active loop. All state is inline and all reads use existing immutable PCM; the audio path adds no allocation, lock, worker wait, native DSP call or additional decoded-buffer ownership.

Release immediately restores neutral transport rate; overlap/add settles back to bit-exact neutral reading within at most two 20-ms hops. Seek/explicit cue resets the stage; paused/EOF output stays silent. The waveform search can displace local transients relative to the nominal source clock, so arbitrary music, transient timing/quality, audible beat alignment and physical latency remain unqualified. This stage handles both nudge and the bounded continuous Sync correction. Musical/transient alignment still requires qualification separately from the nominal source-clock phase.

### Automatic Keylock Sync acquisition

SYNC on a playing prepared Keylock deck compares the matched tempo with its current prepared base. If different, it prepares the matched buffer on the existing worker while retaining the old rate, displays a separate preparing/cancel state, then waits for fresh paired audio frames before phase acquisition. Pending is not reported as active Sync. The request is bound to both source identities, saved grids, command versions, alignment and target range; changed transport/inputs, loading, EOF, changed reference tempo or a thirty-second request timeout cancel it. A second press cancels the request and discards its pending worker result. Native work itself remains non-interruptible; existing job admission limits still apply.

After acquisition, continuous correction remains within +/-2%, preserves the prepared base and uses the existing 100-ms render deadline. No whole-track job is launched on every correction tick. Direct phase alignment requires an already matched prepared base; the exact captured factor is validated again before state mutation. Nudge, manual pitch/transport, changed sources/grids and stale frames release following to neutral. The audible transient phase can differ from nominal source-clock phase because of waveform matching; synthetic tone/clock tests are not musical or hardware acceptance.

## In-track quarter-note meter changes

The grid editor supports a base meter of 1-16 quarter beats per bar and up to sixteen changes starting at bar 2 or later. Use the bar-number and quarter-beat fields followed by SET METER; REMOVE deletes the change at the selected bar. Changes stay in the draft until SAVE; CANCEL discards them. The summary lists the base and changes, and waveform downbeats/bar numbering follow the preview or saved map. Changes are tied to bar numbers: editing earlier meters recomputes later bar positions. BPM/anchor/slip edits retain the map and reject results placing changes outside the loaded source duration. CLEAR discards the map; the selected base meter is retained for setting a new anchor.

SQLite schema 8 adds a bounded JSON meter-map column, migrating earlier grids with an empty map. Reading rejects malformed, excessive, duplicate, unsorted or invalid meter entries; full/delta writes use the existing transactions and recovery path. BeatGrid retains bounded inline Copy state, with no new map allocation or processing in the audio callback. Tempo remains constant and BPM/quantization/auto-loop lengths use quarter beats. Sync alignment choices remain explicit beat periods; other denominators and automatic meter-following bar Sync remain open. Native visual/musical acceptance is not established.

## Tolerant MP3 ID3 input (2026-10-29)

Metadata inspection, offline analysis and deck preparation can recover from the two known leading-ID3 parser failures (invalid text encoding and unsupported compressed frames). Recovery is restricted to MP3 and validates the leading tags before opening an offset-relative seekable view of the audio. It accepts at most eight consecutive ID3v2.2/2.3/2.4 tags and 32 MiB of aggregate leading tag bytes; invalid synchsafe sizes, version/flag fields, out-of-file offsets and mismatched v2.4 footers fail. The file is never rewritten, and normal valid-tag reads retain their previous behavior.

When recovery succeeds, unavailable tag values remain absent and the existing metadata diagnostic contains an explicit ID3-skipped warning; header duration remains available where the audio header provides it. A warning does not mean every audio frame is valid. Previously cached instances of the two exact old errors are retried by the existing storage worker when the file is available. Changed metadata is persisted using existing backfill behavior; successful warnings remain cached and unavailable files do not cause unnecessary catalog writes. No schema migration or automatic repair of media files is involved. Other metadata/audio failures retain their existing errors.

## Selectable cue quantization (2026-10-29)

Each deck has a session-local 1/8, 1/4, 1/2, 1, 2 or 4 beat step, defaulting to one beat. QUANT places new empty cue slots on the nearest selected lattice point of the confirmed manual grid (halfway chooses later). Saved cue timestamps are never resnapped. Next grid schedules an occupied cue at the strictly next representable source-frame grid point and jumps to its exact saved target. Steps are quarter-beat BPM units and anchored at the manual grid anchor; a 4-beat step does not automatically become a bar in another meter.

Both operations use bounded exact binary-rational BPM arithmetic and integer source-frame rounding. Strict-next selection excludes a grid point which rounds onto the current source frame. The source-rate-one edge is covered with a bounded search; ordinary audio rates need the first candidate or its immediate successor. Invalid step indices and steps outside the playable track reject before mutation. The selection is per deck, retained across track replacement during the session and not persisted. The Slint step-property change handler cancels pending cue triggers. Existing trigger guards against loop/nudge/Sync/pending pitch and grid edits remain; this does not introduce loop quantization or a global Quantize mode.

## Global Quantize master (2026-10-29)

It defaults on to preserve the previous opt-in behavior; all three deck preferences still default off. Global Off bypasses those preferences without clearing them or changing the selected cue step. New cues then retain the current source position, occupied cues recall immediately, and new auto-loops start at the playhead. Beat-based auto-loop length still requires a confirmed manual grid. The master does not add quantization to manual loop boundaries or resnap stored cue targets.

Turning Off cancels queued cue triggers on both decks. A direct toolbar event cancels immediately; the property-change handler also handles host/property changes when Slint processes change handlers. Redundant notifications are idempotent, and turning On does not cancel a newly queued trigger. Transport, current loop bounds, pitch, nudge, Sync correction and mixer gains are unchanged by the toggle. Re-enabling restores the retained per-deck choices. Quantization options are disabled while globally bypassed; the master remains usable without loaded tracks. No preference persistence was added in this slice.

## MPEG Layer-3 in WAVE and source diagnostics (2026-10-29)

After the normal parser fails, the shared worker path can expose a verified RIFF/WAVE data region carrying MPEG Layer 3 (fmt code 0x0055). It validates optional leading ID3 tags, declared RIFF/chunk bounds, unique nonempty data and format chunks, a bounded chunk scan and the actual probed MPEG codec. Reads stop at the data boundary, including with trailing bytes outside RIFF; a terminal odd-size data chunk is accepted without reading a pad outside the declared extent. Other codecs disguised by a 0x0055 header are rejected. Metadata, offline analysis and Rodio preparation use this policy; normal supported files retain their original path. Container tags are omitted with an explicit warning; no file is rewritten, and generalized RF64/RIFX or other compressed WAVE support is not implied.

Failed empty inputs report zero bytes; valid leading ID3 spans with at most 128 remaining bytes report the remaining length after a decode/probe failure. This describes failed inspection rather than declaring those remaining bytes recoverable audio. Unrecognized/unsupported WAVE failures receive stable readable diagnostics. Rodio's original error remains available when the independent format parser accepted the original source and recovery does not apply. All inspection and decoding remain on workers, outside real-time callbacks.

## Deck trim and three-band EQ (2026-10-29)

The per-deck chain is fixed-format renderer, Trim/EQ, existing Sink channel/crossfader gain, shared mix, output-pair router and bus sample-peak meter. Trim ranges -12..12 dB; Low/Mid/High range -24..12 dB. Low shelf is 250 Hz, mid peak 1 kHz at Q=1/sqrt(2), high shelf 4 kHz with shelf slope 1; corners are capped at 0.45 times output sample rate. Coefficient design follows the [W3C Audio EQ Cookbook](https://www.w3.org/TR/audio-eq-cookbook/) on the control plane. These are explicit software characteristics, not a measured emulation of the reference hardware, full-kill isolation or a limiter.

An atomic generation-checked snapshot is attempted once per frame without retry/spin. Two independent inline filter-state banks crossfade across ceil(rate/200) complete frames; new edits during a transition coalesce to the latest target and start after that transition. No coefficient interpolation or trigonometry runs in the sample processor. Channel histories are separate; the DSP introduces no source-time/seek/tempo changes. Unchanged flat settings retain unity. State storage is inline for 1..32 output channels; larger default devices fail explicitly rather than bypassing DSP. Track replacement retains deck settings, while replacing filter history; restart does not restore these session-local controls. Existing source-retirement and backend real-time limitations remain separate from the measured allocation-free EQ sample/drop paths.

The GUI EQ button reveals dB controls and per-deck Reset. Invalid/nonfinite values restore the last valid deck settings. Boosts can exceed 0 dBFS, and the existing post-fader bus sample peak includes their signal effect; independent channel meters/clip hold, filter, effects, hardware knob mapping, persistence and native musical/visual qualification remain open.

## Bipolar deck filter (2026-10-29)

The preceding filter limitation is superseded by a fourth fixed biquad stage between the three EQ bands and trim. Exactly zero bypasses the filter; negative values select a second-order Butterworth low-pass and positive values a high-pass, both Q=1/sqrt(2). Let upper=min(20000 Hz,0.45*output rate), lower=min(20 Hz,upper): the negative sweep uses upper*(lower/upper)^abs(value), the positive sweep lower*(upper/lower)^value. Endpoint filtering is not a mute; near-center activation uses the stated finite cutoff and a five-millisecond transition. These are explicit software characteristics, not controller-model emulation or adjustable resonance.

Filter is included in the same coherent atomic generation as gain/EQ, with four inline channel-state stages and the existing bounded two-bank crossfade. Coefficients are designed on the control plane; sample iteration performs no trigonometry, allocation or locking. Latest edits during a transition coalesce. A separate OFF button resets only the filter, while per-deck Reset restores gain/EQ/filter. Invalid or nonfinite filter values restore the prior valid state. Settings survive track replacement but remain session-only. The GUI displays LP/HP sweep percent or FILTER OFF, not a measured hardware cutoff. Independent channel metering, effects, hardware knob mapping and native musical/visual qualification remain open.

## Independent channel sample peaks and clip hold (2026-10-29)

Deck A/B now publish independent sample peaks after EQ/filter/trim but before Sink channel/crossfader gain. Each value is the maximum absolute sample across that deck's output channels in the latest ceil(rate/20)-frame window. Complete frames alone publish, and the wrapper preserves sample values and fixed source format. Unloaded/new source graphs have no peak until a complete window is produced. Each source graph owns its peak state; old graph writes cannot replace the new graph's values. The control plane retains retired meter ownership through the existing queue-retirement acknowledgement before reclaiming it.

Clip hold is separate from the rolling peak: each completed frame with abs(sample)>=1 or a nonfinite sample records an event. This is a digital warning threshold/invalid-input indication, not proof of physical DAC clipping or a true-peak measurement. A deck-level event counter and reset baseline keep the warning through later quiet windows and source/track/Keylock replacements. Clear acknowledges the observed count, so events completed after the reset observation survive. Manual clear or application restart resets the indication; no SQLite setting is written. The A/B meters and clear controls are independent.

The always-visible mixer row shows dBFS and a per-deck CLIP/CLEAR button. LAST marks inactive transport and shows the latest produced window, not a hardware-timed value. Pausing does not synthesize a silent peak; EOF may still produce silence through the installed renderer. Latest-window values can be overwritten before a delayed UI poll, while clip hold retains overrange events. The separate shared bus meter continues measuring after faders and mix. RMS/loudness, true peak, stereo-separated meter bars, hardware metering, musical and native layout qualification remain open.

## Delay effect implementation pending tests (2026-10-29)

These changes have compilation/static-review evidence only; preceding passed-test counts do not qualify this implementation.

Each existing deck Sink feeds a permanent fixed-format deck mixer, then DelaySource, then the shared mix/router/bus meter. Delay is post-fader: echo tails may continue after a fader closes, a deck pauses or a track changes. The existing channel meter remains after EQ/filter/trim and before faders, and therefore excludes delay; the bus meter includes it. A time setting is milliseconds, not grid/tempo synchronization. Delay times are 20-1000 ms, feedback 0-0.85 and wet 0-1. Output is (1-wet)*dry + wet*echo. Bypass ramps wet to zero over ceil(rate/200) complete frames; a zero wet value passes dry directly. Feedback and wet changes are ramped, and delay-time changes blend two taps with latest-target coalescing. Bypassed processors keep warm history. Ring history is not saved.

The engine retains ring owners until its owned device has stopped; injected renderers retain the existing stop/join-before-engine-drop contract. DelaySource itself adds no render-side allocation or locks. The added Rodio mixers still have source-admission locks/small allocations; no complete-graph hard-real-time guarantee is made. Tiny feedback history is zeroed below 1e-30. The existing CLI wait remains source-EOF based, not an effect-tail or physical-output drain guarantee.

## Independent cue engine foundation (2026-10-30)

The engine can select A/B pre-fader headphone cue for mono/stereo tracks on output devices with at least four channels. Logical channels 1/2 carry the master; logical 3/4 carry the sum of selected dry cue decks after EQ/filter/trim and before channel/crossfader gain. The fixed headphone pair is physical 3/4; enabling cue while master is routed there, or routing master there during cue, returns an error without changing the selection. Mono/stereo devices reject independent cue. Neither headphone gain nor cue/master blend, GUI controls, MIDI cue buttons or cue preference persistence is wired in this engine-only slice.

Deck fader/crossfader gain now runs in CueSend before the unity-gain Sink; transport/pause still gates both paths through that Sink. Controls publish per-frame packed gain/cue values, with one control-plane writer. The engine retains their Arc owners across queue retirement. With cue active, both deck effects pass auxiliary audio dry and write zero into auxiliary delay history. CueSend publishes the cue mode actually used by its frame so a simultaneous UI deselection cannot make the effect record headphone audio. No independent cue FX, tail or click-free cue switching is promised. Selected decks are summed without a limiter.

When cue is disabled, existing multichannel source channels and delay processing are preserved. Enabling cue with a loaded track exceeding two source channels is rejected; loading such a track while cue is active is also rejected and preserves the previous deck. This prevents reuse of channels 3/4 from discarding multichannel source content. Normal source/EOF/queue retirement remains in force. The bus clock/meter now sits before physical routing: with cue active only logical master channels 1/2 contribute to its peak; otherwise all logical channels contribute. A multichannel remap's meter therefore describes the logical bus rather than only the physically selected stereo pair.

The new wrapper uses fixed stereo storage and atomic frame snapshots, with no added sample-loop locks/heap operations; the isolated wrapper pull/drop test retains control ownership. Existing Rodio mixer/queue locks and small allocations remain, so this is not a whole-graph hard-real-time guarantee. Hardware listening with independent simultaneous master/cue remains pending until GUI/controller wiring.

## Monitor gain and Cue/Master blend (2026-10-30)

MON now exposes headphone level 0-100 percent and linear Cue/Master mix (0=only selected dry cues, 100=master preview). Physical pair 3/4 renders gain*((1-mix)*cue+mix*logical_stereo_master); MASTER remains unchanged. Gain/mix use one atomic packed snapshot per frame and five-millisecond ramps. Master-only preview reserves 3/4 even when neither deck cue is selected. On the final preview request being disabled, the renderer retains the master-preview branch until the zero-mix ramp finishes, including a frame rendered between route and settings publication. An explicit master reroute to 3/4 takes precedence; output routing changes themselves are not promised click-free. Cue-selection on/off is distinct from parameter smoothing.

The engine rejects nonfinite/out-of-range values, devices below four channels, master/cue collisions and multichannel input conflicts without changing the previous monitor settings. Auxiliary effect history remains excluded while the monitor mix is active, independently of deck cue selection. Monitor settings remain session-only in this slice. MC4000 channel-16 CC12 (Monitor Level) and CC13 (Monitor Pan) feed coalesced latest-value atomics and the same GUI callback as the sliders. No callback formatting/I/O or new sample-loop allocations/locks were introduced. The all-on LED policy is unchanged.
