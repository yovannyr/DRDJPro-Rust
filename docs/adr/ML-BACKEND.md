# A0 — CPU inference backend decision

Date: 2026-11-17. Scope: an isolated Windows x64 experiment, not production AI.
Status: A0 experiment completed; provisional CPU candidate selected for A1.
The preceding honesty corrections are documented in
[AI_REVIEW_FIXES.md](../reviews/AI_REVIEW_FIXES.md). A1 is not started here.

## Contract and experiment

`crates/drdj-ml` is a workspace member but **not an application dependency**.
Default features enable neither runtime. Two optional adapters implement the same
worker-owned `InferenceBackend`; no UI, audio callback, decoder, track-loading
path or analysis-result cache is connected. Calls may block and allocate.
Inputs are trusted local spike fixtures, not arbitrary third-party ONNX graphs.

Candidates are exactly pinned: `ort = 2.0.0-rc.15`, ONNX Runtime CPU 1.31.0
(API31, explicit dynamic load), and `tract-onnx/tract-linalg = 0.23.8` with a
bounded owned Rayon executor. ORT default download/copy/link features and tract's
optional transformer package are disabled. No GPU provider is selected. RC wrapper
API churn and native DLL packaging remain ORT risks; tract operator/export
compatibility must also be established for every future real graph.

The reference graph is a deterministic, untrained 489-byte Conv→Transpose→GRU
ONNX IR8/opset13 fixture generated by Python stdlib. No binary model is committed.
Three checked-in scalar reference cases use the ONNX GRU default equations,
f32-rounded weights and a stricter 1e-5 absolute tolerance. Rust checks fixture
SHA256, outputs, repeated stateless execution, invalid tensors, missing/corrupt/
oversized models and missing/conflicting ORT libraries. Threads 1/2/4 are requested;
small operations may legitimately remain serial. Pools are not a process-wide
hard cap on all runtime/OS threads.

The inspected [Beat This! README](https://github.com/CPJKU/beat_this/blob/b95c8ab0c58c2d9fcfd40508ae8dffbc05ac4f5c/README.md)
describes PyTorch inference/checkpoints; no ready ONNX export was established in
that inspection. It states MIT for code and published weights, while flagging
restrictions on training files. Neither export compatibility nor suitability of
training-data rights for this product has been qualified. Therefore this experiment
uses the plan's synthetic fallback. It downloads no trained weights or PyTorch.

## Measurement method

Host: Windows x64, Intel i7-11850H (8 cores/16 logical), 31.7 GiB physical RAM.
Rust 1.99.1; `ml-spike` profile inherits release, debug=0, incremental=false,
LTO=false, 16 codegen units; exactly one Cargo job. Each candidate's ML-only
measurement target is isolated under the existing target root. This avoids GUI
builds and permits a cold **compilation** with cached Rust sources and no network.
It is not a clean installation/download benchmark or an application release build.

`tools/ml_spike.py` starts a fresh child per backend/thread count. First load
includes runtime/environment setup; warm load reuses OS/runtime state, including
ORT's one shared Environment. Neither means a purged OS file cache. Ten batches
of 75 independent eight-frame inferences are measured. Their median is called a
synthetic minute only by assuming an artificial 10Hz frame rate. This cannot
predict real audio import RTF, preprocessing cost, beat accuracy or inference
with a trained model. Background desktop applications were not controlled.

After inference, the child flushes its result and waits for ACK. Windows
GetProcessMemoryInfo reads its process peak working set while the backend remains
alive. This includes runtime, graph and executable state; it is not allocator-only
RAM, GPU RAM, total machine RAM or an audio-thread allocation measurement.

The original measurements used the 82,887,349-byte GitHub release ZIP
(SHA-256 `3958d8a44984160692c1b4ffd0de3cb48f8c39f9d34bb31e433db06e30b82195`;
17,620,543 bytes retained). Its download URL returned HTTP 404 during A1 CI.

The explicit fetch tool now reads the Windows x64 CPU wheel from the
[ONNX Runtime 1.31.0 PyPI release](https://pypi.org/project/onnxruntime/1.31.0/#files).
It checks the 14,885,750-byte archive against its published SHA-256
`317608967b03807ed4661113b08293fac02a1db6496a6863a07d9f19232936ad`
and extracts the two native DLLs and both license files (19,656,295 bytes).
The temporary download is removed. The Python package is never installed.

## Results and decision

Raw, path-sanitized measurements: [ml-a0-2026-11-17.json](evidence/ml-a0-2026-11-17.json).
Both cold compilations succeeded with `--locked --offline`, after the Rust
sources were cached. An earlier pre-priming attempt correctly failed because
three SHA2 test dependencies were absent; these were explicitly fetched. The
ORT target alone was then cleaned and rebuilt for the final measurement; the
shared application target was untouched. No failures were reclassified as passes.

| Candidate | Cold ML-only compilation | Target files after candidate tests | Probe executable | Additional runtime files |
|---|---:|---:|---:|---:|
| ORT | 75.25 s | 77.14 MiB | 0.43 MiB | 16.80 MiB, two CPU DLLs plus license notices |
| tract | 957.94 s | 797.29 MiB | 25.10 MiB | No separate runtime DLL from this crate |

Target totals include compiler/test artifacts, not source cache or the app;
they were captured before any combined-feature tests. These are one-time local
observations, not statistically controlled build benchmarks. Installed program
size also depends on integration/packaging; the table measures standalone probes.

**Decision:** use **ORT CPU, initially one requested thread**, as the primary
candidate for A1's test-model service. Its substantially smaller observed build
footprint/time and smaller probe-plus-runtime bundle favor the user's storage
constraint. Both meet scalar parity and cached-source offline build criteria.
The tiny graph gives no evidence that extra threads justify competing with audio;
thread policy and active-playback behavior must be qualified in A1.

Keep tract behind the same optional trait as a viable alternative: it has lower
measured process peak RAM and avoids a separate DLL, at a higher build cost and
larger standalone executable here. It is not rejected as numerically incorrect.
This is a **provisional A0 decision for the synthetic service**, not a universal
choice for Beat This!, Demucs, GPU or other operators. Revisit if the selected
real model fails export/parity, its RAM budget, packaging/offline reproducibility
or acceptable end-to-end import time. STFT/complex/transformer export remains
unqualified and cannot be inferred from Conv/GRU success.

The runtime is not enabled in the application. No stems, beat/downbeat labels,
structure markers or production inference service are added by this slice.

## Reproduction and acceptance boundaries

Local completed checks:

- `cargo +1.99.1 test -p drdj-ml --features ort --profile ml-spike --locked --offline`:
  7 passed (3 unit, 4 integration); no ignored tests.
- The same command with `--features tract`: 5 passed (3 unit, 2 integration);
  no ignored tests. Both parity tests cover 1/2/4 threads and repeat all cases.
- `cargo +1.99.1 test -p drdj-ml --no-default-features --locked --offline`:
  3 unit tests passed; no runtime backend initialized.
- `cargo +1.99.1 clippy -p drdj-ml --all-features --all-targets --locked --offline
  -- -D warnings`: passed, checking the combined feature configuration too.
- `python -m unittest discover -s tools -p "test_ml_*.py"`: 3 passed.
- `cargo +1.100.0 clippy --workspace --all-targets --locked --offline --target
  x86_64-pc-windows-msvc -- -D warnings`: passed for the default workspace.
- Full rustfmt and diff checks passed. No warning suppression was introduced.

Independent review: GPT-6.1 Sol, medium, including follow-ups for runtime path
ownership, the shared ORT Environment, peak-memory handoff and CI coverage. Final
static review and independent raw-data/table/test-log comparison found no remaining
blocking findings. The reviewer did not repeat builds or native workflows.

After validation, only the newly created isolated tract compilation profile was
cleaned (832.6 MiB, including the stopped combined-feature attempt). Source,
runtime/fixture generators, measured JSON and text logs remain; a new tract run
requires compilation again. ORT's small target and CPU DLL cache remain available.
The shared application's target was not cleaned. C: had approximately 45.8 GiB
free afterward, a system-wide snapshot rather than a hard Cargo/storage quota.

An optional optimized test run with both features together was stopped **before
test execution** when feature unification triggered another tract-core compilation.
The required backend-specific runs above remain complete. Combined features are
compile/lint checked, not runtime-qualified together by this slice. No test was
newly ignored and no warning was suppressed. An app-wide test/release rerun was
not needed for an experiment with no app dependency; default workspace lint is
checked separately from the feature-enabled backend lint.

Commands and environment variables are in the
[crate README](../../crates/drdj-ml/README.md). Dedicated
`ml-backend-spike.yml` runs per-backend Windows parity at 1/2/4 threads, verifies
cached-source offline tests and strict Clippy. Root Cargo changes trigger this
workflow. Its addition alone is not evidence of an executed GitHub CI run.

The existing application workflow still tests the default (runtime-free) crate.
No current full app suite, native UI, listening, hardware, macOS/Linux ML runtime,
large-model import, GPU, STFT/complex or transformer qualification is inferred.
A1's queue/registry/cache/abandonment/soak tests remain future work. The synthetic
reference does not qualify future Beat This!/Demucs models or their weights.

Primary API/format references inspected: [ort](https://docs.rs/ort/2.0.0-rc.15/ort/),
[tract](https://docs.rs/tract-onnx/0.23.8/tract_onnx/),
[ONNX schema](https://github.com/onnx/onnx/blob/main/onnx/onnx.proto), and the locally
downloaded pinned crate sources. Actual compilation takes precedence over stale
API examples (this ort uses `EnvironmentBuilder::build`, tract plans are `Arc`s).
